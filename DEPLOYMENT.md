# Production deployment

BookFlow uses Render for the Spring Boot API and PostgreSQL, and Vercel for the
Vite frontend.

## Prerequisites

- A Render account connected to this GitHub repository
- A Vercel account connected to this GitHub repository
- An OpenAI-compatible API key for the booking assistant

Never commit production credentials or copy them into a Vite environment
variable. Variables prefixed with `VITE_` are visible in the browser bundle.

## 1. Deploy the API and database to Render

1. In Render, create a new Blueprint from this repository.
2. Render detects `render.yaml` and creates:
   - `bookflow-api`, built from `backend/Dockerfile`
   - `bookflow-db`, a PostgreSQL 16-compatible managed database
3. Enter these prompted secret values:
   - `CORS_ALLOWED_ORIGINS`: the exact Vercel production origin, for example
     `https://your-bookflow-project.vercel.app`
   - `AI_LLM_API_KEY`: the production LLM key
4. Apply the Blueprint and wait for `/api/public/health` to report `UP`.

`JWT_SECRET` is generated by Render. The database connection string, username,
and password are injected from the managed database. The container converts the
PostgreSQL URI to a credential-free JDBC URL, and Flyway applies migrations when
the API starts.

The free Render PostgreSQL plan is suitable only for a portfolio demo: it has no
backups and expires after 30 days. Upgrade it before storing durable data.

## 2. Deploy the frontend to Vercel

1. Import this GitHub repository into Vercel.
2. Set **Root Directory** to `frontend`.
3. Keep the detected Vite build settings:
   - Build command: `npm run build`
   - Output directory: `dist`
4. Add this Production environment variable:

   ```text
   VITE_API_BASE_URL=https://bookflow-api.onrender.com
   ```

   Use the actual Render service URL if Render assigned a different hostname.
5. Deploy. `frontend/vercel.json` provides SPA fallback for deep links such as
   `/book/{slug}/assistant`.

## 3. Finalize CORS

Copy the exact Vercel production origin, without a trailing slash, into the
Render `CORS_ALLOWED_ORIGINS` variable. Multiple origins can be supplied as a
comma-separated list. Redeploy the API after changing it.

Do not use `*`: authenticated browser requests require explicit trusted origins.

## 4. Smoke test

Verify:

1. `GET https://bookflow-api.onrender.com/api/public/health` returns `UP`.
2. Register an owner through the Vercel frontend.
3. Create a service, staff member, working hours, and appointment.
4. Open the public `/book/{slug}` page in a signed-out browser.
5. Ask the assistant for a real slot and verify no appointment exists before
   clicking **Confirm booking**.
6. Confirm the proposal and verify the appointment appears for the owner.

Production disables Swagger and OpenAPI endpoints. Use local development for API
documentation.
